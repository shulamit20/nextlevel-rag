# NextLevel Events – בוט ידע ארגוני (RAG)

בוט צ'אט שעונה על שאלות לקוחות של **NextLevel Events**, חברת אולמות אירועים. הבוט עונה **רק** מתוך מסמכי החברה שבתיקייה `data/`: מחירון, קייטרינג, שירותים נוספים, תהליך הזמנה, תשלומים וביטולים, ותקנון.

הטכניקה היא RAG (Retrieval-Augmented Generation). לכל שאלה הבוט שולף את הקטעים הרלוונטיים מהמסמכים, ומודל השפה מנסח תשובה רק על סמך הקטעים האלה.

## טכנולוגיות

| רכיב | בחירה |
|------|-------|
| תשתית RAG | LlamaIndex |
| מאגר וקטורי | ChromaDB, שמור לדיסק בתיקייה `chroma_db/` |
| מודל שפה | Gemini `gemini-3.5-flash-lite` |
| מודל embedding | Gemini `gemini-embedding-001` |
| ממשק | Streamlit |

## התקנה (Windows PowerShell)

כל הפקודות רצות מתוך תיקיית הפרויקט.

**1. Python 3.10 ומעלה.** בודקים אילו גרסאות מותקנות:
```powershell
py --list
```

**2. סביבה וירטואלית.** בפקודה הבאה כותבים גרסה מהרשימה, 3.10 ומעלה. כאן 3.13 היא רק דוגמה:
```powershell
py -3.13 -m venv venv
```

**3. התקנת החבילות:**
```powershell
.\venv\Scripts\python -m pip install -r requirements.txt
```

**4. מפתח API חינמי.** יוצרים מפתח ב-https://aistudio.google.com/apikey. לא צריך כרטיס אשראי או חשבון חיוב.

**5. קובץ `.env`.** מעתיקים את הקובץ לדוגמה ומדביקים את המפתח אחרי `GOOGLE_API_KEY=`:
```powershell
Copy-Item .env.example .env
notepad .env
```

> אין צורך להפעיל את הסביבה (`Activate.ps1`). כל הפקודות קוראות ישירות ל-`.\venv\Scripts\...`, וכך גם מדיניות ההרצה של PowerShell לא חוסמת אותן.

## הרצה

**1. בדיקת חיבור.** הסקריפט שולח קריאה אחת למודל ה-embedding וקריאה אחת למודל השפה:
```powershell
.\venv\Scripts\python .\check_connection.py
```
אם החיבור תקין, מופיעות שתי שורות `[OK]`.

**2. בניית המאגר (חלק א').** מריצים פעם אחת, ושוב בכל פעם שמסמך בתיקייה `data/` משתנה:
```powershell
.\venv\Scripts\python .\ingest.py
```

**3. הממשק (חלק ב'):**
```powershell
.\venv\Scripts\streamlit run .\app.py
```
הדפדפן נפתח בכתובת http://localhost:8501.
בהרצה הראשונה של Streamlit יופיעה בטרמינל השאלה `Email:`. אפשר פשוט ללחוץ Enter.

## ארכיטקטורה

**חלק א' – בניית המאגר** (`ingest.py`, רץ מראש):
המסמכים נחתכים לקטעים לפי הכותרות שלהם, ולכל קטע מחושב embedding (וקטור). הקטעים נשמרים ב-ChromaDB יחד עם המקור שלהם (קובץ וסעיף).

**חלק ב' – מענה** (`app.py` ו-`answer.py`, בכל שאלה):
1. **שכתוב (רק בשאלת המשך).** מודל השפה מקבל את 3 זוגות השאלה-תשובה האחרונים והופך את השאלה לשאלה עצמאית, למשל "ויש שם חניה?" ל"האם יש חניה באולם הבדולח?".
2. **שליפה.** 5 הקטעים הקרובים ביותר לשאלה (מדד cosine).
3. **תשובה.** מודל השפה מקבל רק את השאלה ואת הקטעים, **בלי ההיסטוריה**, ומחזיר JSON מובנה: תשובה וסטטוס (נענתה / חסר מידע / מחוץ לתחום).
4. **טקסטים קבועים מהקוד.** כשחסר מידע, הקוד מוסיף את פרטי המשרד, כך שה-LLM אף פעם לא כותב מספר טלפון בעצמו.

| קובץ | תפקיד |
|------|-------|
| `config.py` | כל ההגדרות: שמות מודלים, k, טמפרטורות, ההנחיות ל-LLM וטקסטים קבועים |
| `rag.py` | משותף לשני החלקים: מודל ה-embedding, פתיחת המאגר, ופונקציית השליפה `retrieve()` |
| `ingest.py` | חלק א': טעינת המסמכים, חיתוך, embedding ושמירה ב-ChromaDB (מוחק ובונה מחדש) |
| `answer.py` | חלק ב': שכתוב שאלת המשך, שליפה, תשובה מה-LLM, ניסיונות חוזרים ו-log של ה-JSON הגולמי |
| `app.py` | ממשק הצ'אט ב-Streamlit, כולל תצוגה מימין לשמאל וחלונית "מקורות" |
| `check_connection.py` | בדיקה שהמפתח, הרשת ושני המודלים עובדים |
| `check_retrieval.py` | מציג אילו קטעים נשלפים לשאלות בדיקה, בלי LLM |
| `check_answers.py` | מריץ שיחות בדיקה ומדפיס תשובה, שאלה משוכתבת ומקורות |
| `data/` | 7 מסמכי הידע של החברה (Markdown) |
| `docs/DECISIONS.md` | יומן ההחלטות המלא |
| `docs/process/` | תיעוד תהליך העבודה: הסברים לכל שלב, ההנחיה המאושרת, ניתוח באגים |

## החלטות עיקריות

היומן המלא, כולל החלופות שנשקלו: [docs/DECISIONS.md](docs/DECISIONS.md).

- **Gemini לשני המודלים, בשכבה החינמית.** ספק ומפתח אחד, עברית טובה, ובלי עלות.
- **`gemini-3.5-flash-lite` ולא `gemini-3.8-flash`.** ל-3.8-flash בשכבה החינמית מותרות רק 5 בקשות לדקה ו-20 ביום, וגם היו בו עומסים (503).
- **חיתוך לפי כותרות ה-Markdown**, עם תקרה של 512 טוקנים. כך כל קטע הוא נושא אחד, וטבלאות לא נחתכות באמצע.
- **k=5.** עם k=3, שאלות שמשלבות שני מסמכים איבדו קטע.
- **ההיסטוריה משמשת רק לשכתוב השאלה.** היא לא מקור לעובדות: שלב התשובה לא רואה אותה, וכך טעות בתשובה קודמת לא עוברת הלאה.
- **פלט JSON מובנה ממודל השפה.** ה-API אוכף את המבנה ואת הערכים המותרים.
- **טקסטים קבועים נכתבים בקוד,** כמו פרטי המשרד והערת המחיר. כך הם תמיד מופיעים, תמיד באותו ניסוח, ואי אפשר להמציא אותם.
- **שאלה עצמאית לא יורשת פרטים מהשיחה.** זה נאכף בקוד, דרך השדה `depends_on_history`.

## מה הבוט עושה

- עונה **רק** מתוך המסמכים, בשם החברה.
- כשאין לו מידע, הוא אומר זאת, מציע חלופה קרובה שכן קיימת (למשל להקה חיה במקום DJ), ומוסיף את פרטי המשרד.
- מסרב בנימוס לשאלות שלא קשורות לחברה ומזכיר במה הוא כן עוזר.
- מבין שאלות המשך ("ובערב?", "ויש שם חניה?").
- מחשב מחיר כולל לאירוע ומציג פירוט: כל רכיב בשורה נפרדת, ואחריו סה״כ.
- מציג מקורות בחלונית מתקפלת "מקורות": הקטעים שנשלפו, הציון שלהם, ובשאלת המשך גם את השאלה המשוכתבת ואת הפרטים שנלקחו מהשיחה.

## בדיקות

```powershell
.\venv\Scripts\python .\check_retrieval.py   # מה נשלף, בלי LLM
.\venv\Scripts\python .\check_answers.py     # תשובות מלאות, כולל שאלות המשך
```
`check_answers.py` ממתין 9 שניות בין שאלות, כדי לא לחרוג ממכסת השכבה החינמית (15 בקשות לדקה).

**מה נבדק:**
- **מחיר מדויק:** האולם הראשי במשמרת ערב עולה 15,000 ₪. זה נבדק למרות שבאותה שליפה מגיע גם קטע הדוגמה, שבו מופיע מחיר של אולם אחר.
- **חישוב משני מסמכים:** ערב באולם הבדולח ל-200 אורחים עם תפריט בשרי. 16,000 + 220×200 = 60,000 ₪, עם פירוט.
- **חסר מידע:** "כמה עולה DJ?". הבוט אומר שאין לנו, מציע להקה חיה ב-8,000 ₪, ומוסיף את פרטי המשרד.
- **מחוץ לתחום:** שאלה על מזג האוויר.
- **שאלות המשך:** "ובערב?" ו-"ויש שם חניה?".
- **שאלה עצמאית אחרי שיחה:** "כמה עולה האולם הראשי בערב?" אחרי שאלה עם 200 אורחים. התשובה מציינת קודם את מחיר האולם עצמו, ואחריו סה״כ שמסומן "סה״כ משוער לאירוע".
- **שגיאות הקלדה:** "בבניבקכ כמה אולמותצ?". השאלה מתוקנת לפני השליפה.
- **תצוגה:** שעות ומספרי טלפון לא מתהפכים בטקסט מימין לשמאל.

## מגבלות ידועות

- **מכסת השכבה החינמית:** `gemini-3.5-flash-lite` מאפשר 15 בקשות לדקה, ושאלת המשך צורכת 2 בקשות. מעבר למכסה מתקבלת שגיאה 429. בנוסף, בזמני עומס Google מחזיר שגיאה 503. הקוד מנסה שוב עד 3 פעמים, ואם לא הצליח, מציג הודעה קבועה ומפנה למשרד.
- **אין מידע חי:** הבוט לא יודע אילו תאריכים פנויים ומה הסטטוס של הזמנה. הוא עונה רק מהמסמכים.
- **זיכרון שיחה:** רק 3 זוגות השאלה-תשובה האחרונים.

## הערה: רשת עם סינון HTTPS (למשל נטפרי)

ברשת שבודקת תעבורת HTTPS, Python לא מכיר את תעודת האבטחה של המסנן, ומחזיר את השגיאה `CERTIFICATE_VERIFY_FAILED`. לכן בראש כל קובץ שמריצים יש שתי שורות של `truststore`. הן גורמות ל-Python לבדוק תעודות דרך מאגר התעודות של Windows, שבו תעודת המסנן כבר מותקנת. ברשת רגילה הן לא משנות דבר.
