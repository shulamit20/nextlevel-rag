# באג: שורת הסה"כ נחתכת + נקודות הרשימה בצד שמאל

## מה הבדיקה הראתה

הרצתי פעמיים, בלי ממשק, את השאלה "כמה עולה ערב באולם הבדולח ל-200 אורחים עם תפריט בשרי?" והדפסתי את הטקסט הגולמי שהקוד מקבל.

**בשתי הריצות הטקסט הגיע שלם ונכון:**

```
- מחיר בסיס (ערב, אולם הבדולח): 16,000 ₪
- קייטרינג: 220 ₪ × 200 אורחים = 44,000 ₪
- **סה"כ: 60,000 ₪**
```

כלומר הבאג **לא קורה בכל פעם**. בריצה שלך הוא קרה, ובשתי הריצות שלי לא.

---

## באג 1: הסה"כ נחתך – הסיבה

**החיתוך קורה בדיוק בתו `"` שבתוך המילה `סה"כ`.**

1. ה-LLM לא מחזיר טקסט חופשי, אלא JSON (החלטה מ-02.11: answer / status / has_price).
2. ב-JSON, התו `"` מסמן **סוף מחרוזת**. כדי לכתוב `"` בתוך התשובה, ה-LLM צריך לכתוב `\"` (עם לוכסן לפניו).
3. בעברית, `"` משמש גם לראשי תיבות (סה"כ, ש"ח, בע"מ). לפעמים המודל כותב אותו בלי הלוכסן.
4. ה-API של Gemini מכריח את הפלט להיות JSON תקין, ולכן ברגע שהמודל כתב `"`, המחרוזת `answer` **הסתיימה שם**. מה שנשאר מהתשובה הוא `- **סה`, ואחריו המודל המשיך ישר ל-`status` ול-`has_price`.
5. לכן הופיע גם משפט המחיר: `has_price` הגיע `true`, והקוד הוסיף את המשפט כרגיל.
6. רואים את הכוכביות `**` כי סימן הסגירה של ההדגשה נחתך יחד עם שאר השורה.

**למה דווקא בשאלה הזו:** במסמך `02_hall_prices.md` (שורה 24) קטע הדוגמה כתוב בדיוק כך: `- **סה"כ: 26,000 ₪**`. המודל מעתיק את הפורמט, כולל ה-`"`.

**בדיקת הבעיה מצד אחר:** כל ראשי תיבות בתשובה (ש"ח, בע"מ, מע"מ) חשופים לאותה בעיה. זו לא בעיה רק של הסה"כ.

### אפשרויות תיקון

| | אפשרות | יתרונות | חסרונות |
|---|---|---|---|
| **א** | **להוסיף להנחיה כלל:** "בראשי תיבות כתוב גרשיים עבריים (״) ולא מירכאות (\")" | שינוי של שורה אחת; ה-`״` העברי לא מסמן סוף מחרוזת, ולכן לא ישבור את ה-JSON; נראה זהה למשתמש | שינוי בהנחיה המאושרת (צריך את אישורך); זו הוראה, לא אכיפה, אז המודל עלול לפעמים לא לציית |
| **ב** | **לבדוק בקוד אם התשובה נחתכה** (למשל `**` שלא נסגר) ולנסות שוב | רשת ביטחון גם כשהמודל לא ציית | שביר: מזהה רק סוגים מסוימים של חיתוך; חיתוך בלי `**` (למשל "ש" בסוף משפט) לא יתגלה |
| **ג** | **לוותר על JSON לטקסט התשובה:** המודל כותב טקסט חופשי, ובסוף שורת סימון (`STATUS: missing`) | הבעיה נעלמת מהשורש | מבטל החלטה קיימת (פלט מובנה); חוזרים לפענוח טקסט, שהוא בדיוק מה שרצינו להימנע ממנו |
| **ד** | **להחליף במסמכים `"` ב-`״`** | המודל יעתיק את הצורה הנכונה מהקטעים | מטפל רק בראשי תיבות שהמודל מעתיק; ראשי תיבות שהוא כותב בעצמו עדיין בסיכון; צריך ingest מחדש |

**ההמלצה שלי: א'**, ואם רוצים ביטחון נוסף, להוסיף גם את ב'. א' מטפלת בסיבה עצמה ועולה הכי מעט. ג' נכונה עקרונית אבל מבטלת החלטה שעבדה טוב.

**איך נבדוק שהתיקון עבד:** להריץ את השאלה כ-10 פעמים ולוודא שבכולן יש `60,000 ₪`. (הבאג לא קורה בכל פעם, אז ריצה אחת לא מוכיחה כלום.)

## עדכון (03.11): איך הקוד מפענח את ה-JSON בפועל

ההשערה הייתה שיש פענוח סלחני (regex או תיקון JSON). בדקתי את כל השרשרת, והפענוח **מחמיר**:

1. `answer.py:76` קורא ל-`llm.structured_predict(LLMReply, ...)`.
2. LlamaIndex (`llama_index/llms/google_genai/base.py:695-696`) שולח ל-API את
   `response_mime_type = "application/json"` ואת `response_schema = LLMReply`.
   **זה כבר structured output / JSON mode של ה-API.**
3. google-genai (`google/genai/types.py:9014`) מפענח עם
   `LLMReply.model_validate_json(text)`, שהוא פענוח JSON מחמיר של pydantic (כמו `json.loads` ובדיקת שדות). כשהפענוח נכשל, `parsed` נשאר ריק.
4. LlamaIndex (`base.py:721`) מנסה שוב `model_validate_json`. אם גם זה נכשל, נזרקת שגיאה, `answer.py` מנסה עוד פעם, ובסוף מוצגת הודעת השגיאה הקבועה.

הזרימה היא `structured_predict` ← `response_schema` ← `model_validate_json` (מחמיר) ← שגיאה ← ניסיון חוזר ← הודעת שגיאה.

**המסקנה:** JSON לא תקין **לא יכול** להגיע ללקוח חתוך. הוא היה נגמר בהודעת שגיאה. לכן ה-JSON שהגיע היה **תקין**, למשל:

```json
{"answer": "- מחיר בסיס ...\n- **סה", "status": "answered", "has_price": true}
```

ב-structured output, ה-API מכריח כל טוקן לשמור על JSON תקין. כשהמודל כתב `"` אחרי `סה`, זו נחשבה סגירה חוקית של המחרוזת, והמודל נאלץ להמשיך ישר ל-`status` ול-`has_price`. החיתוך קורה **אצל Gemini בזמן הכתיבה**, לא אצלנו בפענוח.

**לכן מעבר ל-`json.loads` לא יתקן את הבאג.** הוא היה מקבל בדיוק את אותו JSON תקין ואותה תשובה חתוכה.

**הסתייגות:** את ה-JSON הגולמי מהריצה שלך לא ראיתי, כי הקוד לא שומר אותו. ההסבר הזה הוא ההסבר היחיד שמתאים גם לפענוח המחמיר וגם למה שראית (`**סה` ומשפט המחיר), אבל הוא עדיין לא הוכח.

### אפשרויות מעודכנות לבאג 1

| | אפשרות | מה זה פותר |
|---|---|---|
| **א** | כלל הגרשיים העבריים (״) בהנחיה | מקטין מאוד את הסיכוי: `״` לא סוגר מחרוזת JSON |
| **ב** | בדיקה בקוד: `**` שלא נסגר, או תשובה שנגמרת באמצע ראשי תיבות ← ניסיון חוזר | רשת ביטחון חלקית |
| **ג** | טקסט חופשי במקום JSON, ושורת סימון בסוף | מעלים את הבעיה מהשורש, אבל מבטלים את החלטת הפלט המובנה |
| **ה (חדש)** | לשמור ב-log את ה-JSON הגולמי של כל תשובה | לא מתקן, אבל **מוכיח** את הסיבה בפעם הבאה שזה יקרה |

**ההמלצה שלי: א' + ה'.** א' מורידה את התקלה, ו-ה' מאפשרת לאמת שזו באמת הסיבה. ל-ה' צריך לקרוא ל-Gemini דרך `google-genai` ישירות במקום דרך `structured_predict`, כי LlamaIndex לא מחזיר את הטקסט הגולמי. זה גם נותן לך את מה שביקשת: `json.loads` רגיל עם טיפול בשגיאה, וקוד שרואים בו כל שלב.
