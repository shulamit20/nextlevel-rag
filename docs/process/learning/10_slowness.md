# למה הבוט עונה לאט – אבחון

> סטטוס: **הוחלט ונבנה (03.11)** – אפשרות א'. שני אובייקטי ה-LLM נוצרים פעם אחת בראש
> `answer.py`, עם `max_retries=0` וטמפרטורות מ-config; בלי `max_tokens`/`context_window`.

## 1. מה מדדתי

הרצתי סקריפט מדידה (מחוץ לפרויקט) שמודד כל שלב בנפרד:

| שלב | זמן |
|------|------|
| טעינת הספריות (import) – פעם אחת כשהשרת עולה | ~4.1 שנ' |
| פתיחת המאגר (`load_index`) – פעם אחת, שמור ב-`cache_resource` | ~0.9 שנ' |
| שליפה (embedding של השאלה + חיפוש ב-Chroma) | 0.4–0.75 שנ' |
| **יצירת אובייקט `GoogleGenAI(...)` בלבד, בלי לשאול כלום** | **~1.0 שנ'** |
| קריאת תשובה ל-LLM עם אובייקט שכבר קיים | ~1.0 שנ' |
| קריאת תשובה ל-LLM דרך `answer_from_chunks` (יוצרת אובייקט חדש) | 2.2–4.2 שנ' |
| שאלת המשך מלאה (`ask` עם היסטוריה) | ~4 שנ' |

**המסקנה:** יצירת אובייקט ה-LLM לוקחת בערך כמו הקריאה עצמה.

## 2. למה יצירת האובייקט איטית

בספרייה `llama_index.llms.google_genai`, בתוך הבנאי (`__init__`) של `GoogleGenAI`:

```python
# only get model meta data if max_tokens or context_window is not specified
if max_tokens is None or context_window is None:
    model_meta = client.models.get(model=model)
```

כלומר: כל פעם שיוצרים `GoogleGenAI(...)` בלי `max_tokens` ו-`context_window`,
הספרייה **פונה לשרת של Google** כדי לשאול "מה הנתונים של המודל הזה?".
זו קריאת רשת מלאה (כולל דרך נטפרי), בערך שנייה אחת.

## 3. איפה זה קורה אצלנו

ב-[answer.py](../answer.py) נוצר אובייקט חדש **בכל קריאה**:

- `rewrite_question` → `GoogleGenAI(...)` חדש (רק בשאלת המשך)
- `answer_from_chunks` → `GoogleGenAI(...)` חדש (בכל שאלה)

ולכן:

| סוג שאלה | קריאות "מבוזבזות" | זמן מבוזבז בערך |
|-----------|---------------------|-------------------|
| שאלה ראשונה | 1 | ~1 שנ' מתוך ~2.5–3 |
| שאלת המשך | 2 | ~2 שנ' מתוך ~4–5 |
| ניסיון חוזר (retry) | עוד אחת לכל ניסיון | |

בערך **40–50% מזמן ההמתנה** הוא קריאות שלא צריך.

השאר (embedding, ה-LLM עצמו, שלב השכתוב) – זה המחיר הרגיל של RAG עם API חיצוני
ושל ההחלטה מ-02.11 לשכתב שאלות המשך. אין שם בעיה.

## 4. אפשרויות לתיקון (צריך החלטה שלך)

**א. ליצור את שני אובייקטי ה-LLM פעם אחת ולהשתמש בהם שוב** *(ההמלצה שלי)*
- למשל: פונקציה שמחזירה את ה-LLM ושומרת אותו (כמו `get_index` עם `st.cache_resource`),
  או משתנה ברמת הקובץ ב-`answer.py`.
- ✅ חוסך את כל הקריאות המיותרות, גם בניסיונות חוזרים.
- ✅ לא משנה שום התנהגות של המודל.
- ➖ שינוי קטן במבנה `answer.py` (צריך שני אובייקטים – טמפרטורה 0 לשכתוב, 0.2 לתשובה).

**ב. להעביר `context_window` ו-`max_tokens` בבנאי, כדי שהספרייה תדלג על הקריאה**
- ✅ שינוי של שורה אחת בכל מקום.
- ➖ `max_tokens` **מגביל את אורך התשובה** – אם נבחר מספר קטן מדי, תשובות ייחתכו.
  זו החלטה חדשה על התנהגות הבוט, לא רק על מהירות.
- ➖ צריך לדעת את הערכים הנכונים למודל, ולעדכן אם מחליפים מודל.

**ג. שתיהן** – אין תועלת נוספת משמעותית מעבר לא'.

## 5. דברים שבדקתי ואינם הבעיה

- **פתיחת המאגר** – כבר שמורה ב-`@st.cache_resource` ב-[app.py](../app.py), נטענת פעם אחת.
- **החיפוש ב-Chroma** – מהיר מאוד; רוב 0.4–0.75 השניות של השליפה הן ה-embedding ברשת.
