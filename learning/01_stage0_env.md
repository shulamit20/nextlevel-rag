# שלב 0 – סביבה ובדיקת חיבור

## למה השלב הזה קיים
לפני שכותבים שורת RAG אחת, צריך לוודא שלושה דברים:
1. **ש-Python מוכן** – גרסה מתאימה, סביבה וירטואלית (venv) והספריות הנכונות.
2. **שאפשר להגיע ל-Gemini דרך נטפרי** – גם הכתובת וגם תעודת האבטחה.
3. **שהמפתח והמודלים עובדים** – קריאת embedding אחת וקריאת LLM אחת.

אם אחד מהם נכשל כשכבר כתבנו את `ingest.py`, יהיה קשה לדעת אם הבעיה בקוד או בסביבה. לכן בודקים אותם קודם, כל אחד בנפרד.

## ההחלטות הפתוחות בשלב הזה

### 1. איזה מודל שפה (LLM) בדיוק
הוחלט "Gemini Flash, שכבה חינמית". נשאר לבחור **איזה** Flash. לפי התיעוד היום שני המודלים האלה **חינמיים**:

| אפשרות | יתרונות | חסרונות |
|---|---|---|
| **`gemini-3.8-flash`** ⭐ | ה-Flash החזק ביותר; טוב יותר בעברית, בחישובי מחיר ובהחזרת פורמט מסודר (answer/status/has_price) | מעט איטי יותר; מכסה יומית חינמית אולי נמוכה יותר |
| `gemini-3.5-flash-lite` | הכי מהיר וזול; מכסה חינמית בדרך כלל גבוהה יותר | פחות מדויק בהוראות מורכבות – וההנחיה שלנו מורכבת (8 כללים + פורמט) |

**המלצה:** `gemini-3.8-flash`. ההנחיה דורשת דיוק (מחירים, סימון סטטוס), וזה בדיוק מה שמודל חלש יותר מפספס. השם נשמר בקובץ ההגדרות, כך שאפשר להחליף בשורה אחת.

### 2. איזה מודל embedding
| אפשרות | יתרונות | חסרונות |
|---|---|---|
| **`gemini-embedding-001`** ⭐ | מודל טקסט; מקבל `task_type` (שונה למסמך ולשאלה) ש-LlamaIndex כבר יודע להעביר; ותיק ויציב | לא החדש ביותר |
| `gemini-embedding-2` | החדש ביותר, תומך גם בתמונות/וידאו | ההבחנה בין מסמך לשאלה נעשית ב**קידומת טקסט** ידנית (`task: question answering`) – עוד דבר לבנות ולהסביר; את התמונות אנחנו לא צריכים |

**המלצה:** `gemini-embedding-001`. אנחנו צריכים רק טקסט, והוא נותן את ההבחנה "מסמך / שאלה" בלי קוד נוסף.

> **למה זה חשוב שיש הבחנה בין מסמך לשאלה?** שאלה ("כמה עולה האולם?") וקטע מסמך ("מחיר האולם במשמרת ערב: ...") נראים שונה מאוד. מודל שיודע "זו שאלה, תחפש לה תשובה" מקרב את הווקטור של השאלה לווקטור של הקטע שעונה עליה.

> ⚠️ זכרי מיומן ההחלטות: החלפת מודל embedding בהמשך = בניית המאגר מחדש.

## עדכון: נתקלנו בבעיית התעודה של נטפרי (כצפוי)

### מה קורה
נטפרי "פותחת" כל חיבור HTTPS כדי לסנן אותו, וחותמת עליו בתעודה **שלה**. הדפדפן ו-Windows סומכים עליה, כי היא הותקנה במחשב. Python לא, משתי סיבות שבדקתי:

| בדיקה | תוצאה | פירוש |
|---|---|---|
| Python רגיל (מאגר התעודות של Windows) | ❌ `CA cert does not include key usage extension` | Python מכיר את תעודת נטפרי, אבל **Python 3.13 מחמיר** ודורש שדה ("key usage") שחסר בתעודה שלה |
| אותו דבר, בלי ההחמרה | ✅ עובר | זו אכן הבעיה היחידה ב-Python |
| רשימת התעודות ש-ספריית Gemini משתמשת בה (`certifi`) | ❌ `unable to get local issuer certificate` | ספריית Gemini לא מסתכלת במאגר של Windows בכלל, אלא ברשימה פרטית משלה – ושם נטפרי לא נמצאת |
| `truststore` | ✅ עובר | ראו אפשרות א' |

**חשוב:** זו לא תקלה בקוד, ואין כאן "כיבוי אבטחה". השאלה רק **איך לגרום ל-Python לסמוך על אותה תעודה שהמחשב כבר סומך עליה**.

### האפשרויות

| אפשרות | איך | יתרונות | חסרונות |
|---|---|---|---|
| **א. `truststore`** ⭐ | שתי שורות בתחילת כל קובץ שמריצים (`check_connection.py`, `ingest.py`, `app.py`): Python בודק תעודות **דרך Windows**, בדיוק כמו הדפדפן | עבד בבדיקה; פותר את שתי הבעיות יחד; אצל המרצה (בלי נטפרי) פשוט עובד כרגיל; הספרייה כבר הותקנה ממילא (תלות של חבילה אחרת) – רק מוסיפים אותה ל-`requirements.txt` | שתי שורות "של סביבה" בקוד; ספרייה ישירה נוספת |
| ב. להתקין Python 3.12 + המדריך של נטפרי | להוריד Python 3.12 (בלי ההחמרה), לבנות venv מחדש, ולהגדיר משתנה סביבה `SSL_CERT_FILE` לקובץ תעודות שמשלב את נטפרי | אפס שינוי בקוד | התקנה ידנית; משתנה סביבה במחשב שקל לשכוח; כל מחשב עם נטפרי צריך את אותה הגדרה |
| ג. לבטל את ההחמרה בקוד | ליצור בעצמנו "הקשר SSL" בלי ההחמרה ולהעביר אותו לספריית Gemini | בלי ספרייה נוספת | קוד מסובך שנוגע בפנים של ספריית Gemini; מחליש בדיקה שנועדה להגן – קשה להצדיק מול מרצה |

**המלצה:** א' (`truststore`). זו הדרך המקובלת היום לסביבות ארגוניות עם proxy כמו נטפרי, והיא לא מחלישה שום בדיקה: היא רק אומרת ל-Python "תסמוך על מה ש-Windows סומך".

✅ **נבחר: א'.** נוסף ל-`check_connection.py` ול-`requirements.txt`, ויתווסף גם ל-`ingest.py` ול-`app.py`.

### מה `check_connection.py` עושה, שורה אחר שורה
1. `truststore.inject_into_ssl()` – תעודות דרך Windows (נטפרי).
2. `load_dotenv()` – קורא את `.env` ומכניס את המפתח למשתני הסביבה. ספריית Gemini מוצאת אותו לבד לפי השם `GOOGLE_API_KEY`, כך שהמפתח **לא מופיע בקוד בשום מקום**.
3. אם אין מפתח – עוצר עם הודעה ברורה, במקום שגיאה מבלבלת של Google.
4. **embedding:** הופך משפט בעברית לווקטור ומדפיס כמה מספרים יש בו (צפוי: 3072) ואת 5 הראשונים.
5. **LLM:** מבקש מהמודל לענות "OK" ומדפיס את התשובה.

> שימי לב: שני המודלים מוגדרים דרך `config.MODEL_NAME`, לא כטקסט בקוד – בדיוק לפי ההחלטה "שמות מודלים בקובץ הגדרות".

## איך לבדוק (מה שאת צריכה לעשות)

1. **ליצור מפתח:** להיכנס ל-https://aistudio.google.com/apikey → "Create API key" → להעתיק.
   (אם האתר חסום בנטפרי – זו הבקשה שכבר ממתינה אצלם.)
2. **ליצור `.env`:** בתיקיית הפרויקט, להעתיק את `.env.example` לקובץ חדש בשם `.env`, ולהדביק את המפתח אחרי `=` (בלי רווחים ובלי מרכאות).
3. **להריץ** בטרמינל של VS Code, מתוך תיקיית הפרויקט:
   ```
   venv\Scripts\python check_connection.py
   ```
4. **תוצאה צפויה:**
   ```
   [OK] Embedding (gemini-embedding-001): vector of 3072 numbers
        first 5: [...]
   [OK] LLM (gemini-3.8-flash): OK
   ```

### אם משהו נכשל
| הודעה | פירוש |
|---|---|
| `GOOGLE_API_KEY is missing` | הקובץ `.env` חסר, נקרא אחרת (למשל `.env.txt`), או שהמפתח לא הודבק |
| `API key not valid` / `400` | המפתח הועתק לא נכון |
| `429` / `RESOURCE_EXHAUSTED` | עברנו את המכסה החינמית – לחכות דקה ולנסות שוב |
| `CERTIFICATE_VERIFY_FAILED` | תעודת נטפרי – תשלחי לי את ההודעה המלאה |
| `403` / דף חסימה של נטפרי | הכתובת חסומה – צריך לבקש מנטפרי לפתוח את `generativelanguage.googleapis.com` |

> ✅ **אומת 02.11:** שתי הקריאות עברו – embedding של 3072 מספרים, וה-LLM ענה "OK". הסביבה, נטפרי, המפתח ושני המודלים עובדים.
> ⏱️ ההרצה לקחה יותר מ-2 דקות. כנראה הייבוא הראשון של LlamaIndex (קומפילציה ראשונה של הקבצים) או השהיה ברשת. נמדוד שוב בשלב 1 ונראה אם זה חוזר.

## ❓ שאלת הבנה (למרצה)
**"למה המפתח נמצא ב-`.env` ולא ב-`config.py`, אם שניהם קובצי הגדרות?"**

<details>
<summary>כיווני תשובה</summary>

`config.py` עולה לגיט, כדי שכל מי שמריץ את הפרויקט יקבל את אותן הגדרות (אותם מודלים, אותו k). המפתח הוא **סוד אישי**: מי שמחזיק אותו יכול להשתמש במכסה שלך על חשבונך. לכן הוא בקובץ נפרד שנמצא ב-`.gitignore`, וכל אחד יוצר לעצמו `.env` עם המפתח שלו לפי התבנית `.env.example`.
</details>
